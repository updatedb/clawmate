# 多用户与子目录授权设计

## 目标

将 ClawMate 从单用户、全局 root 列表模式升级为：一个系统根目录、一个管理员、多个普通用户，以及按系统根目录子目录分配的访问权限。管理员在首页设置弹窗中维护用户和授权目录；普通用户只能访问获授目录。

## 范围

本设计包括账户、首次登录改密、用户 rootdir 授权、单一系统根目录、设置弹窗和后端强制授权。它不包括角色层级、共享目录的读写权限差异、外部身份提供商、数据库或多租户隔离。

## 配置与数据

`config.json` 是系统配置，只定义一个绝对路径的 `system_root_dir`，以及现有端口、Agent、OpenClaw 等运行参数。该目录是唯一的文件系统授权上界；它本身及其全部子内容始终可被管理员访问。

`users.json` 是私有运行时用户配置，不提交到 Git。每个用户保存稳定 ID、唯一用户名、bcrypt 密码哈希、管理员标志、首次改密标志，以及相对于 `system_root_dir` 的 `root_dirs` 列表。例如：

```json
{
  "users": [
    {
      "id": "u-example",
      "username": "writer",
      "password_hash": "bcrypt-encoded-password-hash",
      "is_admin": false,
      "must_change_password": false,
      "root_dirs": ["webprojects/clawmate", "helper/3gpp"]
    }
  ]
}
```

`root_dirs` 必须是系统根目录下已存在目录的相对路径。任何解析结果都必须在解析后仍位于 `system_root_dir` 内，且不能通过 `..`、绝对路径或符号链接越界。

## 初始账户与迁移

首次未发现 `users.json` 时，系统生成 `admin / password` 管理员，`must_change_password=true`。初始管理员成功登录后必须修改密码：未改密会话仅能调用身份查询、修改密码和登出接口，其他受保护业务接口均返回拒绝响应。密码更新成功后即时解除限制。

现有多项 `roots` 配置迁移为单一 `system_root_dir` 边界。若旧 root 路径无法收纳在选定系统根目录内，启动/迁移必须显式报错，不得隐式扩大访问范围。

## 会话与授权

登录按用户名从 `users.json` 读取账户并验证密码哈希。会话保存 `user_id`、`username`、`is_admin` 和 `must_change_password`，不把密码或哈希写入会话响应。

所有原本接受 `root` 参数的文件、搜索、项目、反馈、Agent 与 WebSocket 路由，统一通过授权解析器取得目录：

- 管理员可取得系统根目录本身及其任意安全子目录。
- 普通用户只能取得其 `root_dirs` 中的已授权目录；伪造其他 root 或路径返回 403。
- 前端的 root 选择列表仅显示可用目录，但这不是授权依据；服务端校验是唯一安全边界。

## 设置界面

首页顶栏新增管理员专用 `btnSettings`，移动端在既有“更多”菜单中提供同一入口。点击打开居中 `settingsModal`，复用首页既有 `.modal-overlay` 与 `.modal-box`，支持关闭按钮、遮罩点击和 Escape；不使用右侧推挤式面板。

弹窗有两个分组：

1. **用户与密码**：显示用户摘要；管理员可创建用户、修改用户名、重设密码和删除普通用户。禁止删除当前管理员或最后一个管理员。创建用户时必须设置初始密码。
2. **Rootdir 授权**：选择某个用户后，从系统根目录的子目录树选择一个或多个目录，保存为该用户的 `root_dirs`。创建用户流程也包含此多选项。普通用户至少有一个授权目录。

普通用户不接收、也不渲染设置入口。接口响应不返回任何密码哈希。

## API 契约

- `GET /api/clawmate/auth/me`：返回当前用户的公开摘要、管理员标志、首次改密状态和可见 rootdir 摘要。
- `POST /api/clawmate/auth/change-password`：供当前已登录用户更新密码；初次管理员改密会清除会话的限制状态。
- `GET /api/clawmate/settings/users`：管理员取得用户摘要和系统根目录下可选目录信息。
- `POST /api/clawmate/settings/users`：管理员创建用户并设置 rootdir 列表。
- `PATCH /api/clawmate/settings/users/{user_id}`：管理员更新用户名、重设密码、管理员标志或授权目录。
- `DELETE /api/clawmate/settings/users/{user_id}`：管理员删除普通用户，执行管理员与最后管理员保护。

所有设置路由要求管理员身份，且在首次改密完成前不可使用。输入校验错误返回 422；未认证返回 401；未授权返回 403；不存在用户或目录返回 404；配置/持久化失败返回明确的非敏感错误。

## 持久化与错误处理

`users.json` 的写入采用同目录临时文件加原子替换，避免中断产生半写入文件。读取损坏或缺失配置时不能静默生成非预期账户；仅缺失且无历史配置的首次初始化可生成默认管理员。密码、哈希、会话 ID 和系统绝对路径不写入浏览器日志或错误详情。

## 测试与验收

后端回归测试覆盖：默认管理员首次登录限制及改密解锁、用户创建和密码哈希、响应不泄露哈希、删除保护、根目录子路径与符号链接边界、普通用户 root 列表过滤、以及伪造 root 参数的 403。配置测试覆盖单一系统根目录解析和旧多 root 的显式迁移错误。

前端契约测试覆盖 `btnSettings`、移动端更多菜单入口、`settingsModal`、两个分组、管理员可见性和用户 rootdir 多选。浏览器验收覆盖管理员创建用户并分配目录、普通用户登录后只看见获授 rootdir、以及首次管理员改密流程。静态/单元测试不能替代该浏览器验证。
