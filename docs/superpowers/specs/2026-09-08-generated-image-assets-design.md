# 受控生成图片资产设计

## 目标与范围

ClawMate 将图片预览升级为受控资产工作台。用户可从图片预览页发起生成、参考图编辑和变体探索；后台使用已配置的 Agent/CLI（`codex`、`claude` 或 `openclaw`），不调用 OpenAI Platform API，也不向浏览器暴露密钥。

首版只支持一张源图或无源图的单一任务，生成 1--4 个候选。用户可以对候选继续编辑，并逐张采用。多源批量任务沿用相同任务协议，但不在首版交付。

不在范围内：直接覆盖源图、浏览器 Base64 传输、任意目录写入、从 CLI 标准输出解析资产、无用户确认的自动保存。

## 用户体验

图片预览默认保持现有的只读浏览、缩放与同目录导航。仅当当前文件是图片时显示“编辑图片”入口。进入编辑态后，预览中心仍展示原图，右侧以符合现有互斥面板规则的“生成资产”面板承载任务表单和候选结果；打开该面板会关闭反馈、Agent 终端和项目面板。

表单字段为：任务类型（生成新图、基于当前图编辑、基于当前图生成变体）、修改说明、用途、主题目录、目标尺寸、候选数量（1--4）、可选附加参考图。提交后，页面显示批次状态而不是把原图替换为结果。

一个批次进入 `queued`、`running`、`awaiting_review`、`failed`、`cancelled` 或 `adopted` 状态。候选图单独显示其说明、尺寸、来源和操作：采用、继续编辑、再生成、删除。采用一张候选只会保存该候选，不影响同批其他候选；采用后的候选仍可查看溯源信息。

项目文件变化沿用现有约定：提示用户刷新目录或文档，不自动刷新当前预览。

## 数据与文件边界

每个任务在项目根下创建：

```text
.clawmate/generated-tasks/<task-id>/
  request.json
  result.json
  candidates/<candidate-id>.png
```

服务端创建 `request.json`，包含经验证的 root、项目相对路径、源图相对路径、附加参考图相对路径、任务类型、用户文本、尺寸、数量、选定 Agent 后端与创建时间。绝不写入密钥、会话令牌或绝对项目外路径。

Agent 仅可把文件写入该任务目录，并以 `result.json` 回传候选清单。每个候选包含 `id`、`file`、`summary`、`width`、`height` 和可选的 `parent_candidate_id`。服务端拒绝路径逃逸、缺失或非图片文件、超出请求数的候选以及不在任务目录内的文件。

用户采用后，服务端将经验证的候选复制到项目内 `assets/generated/<sanitized-topic>/`，使用不冲突的文件名，并在该主题目录追加或建立 `manifest.json`。manifest 记录：任务和候选 ID、源文件和参考文件、任务类型、修改说明、用途、尺寸、Agent 请求/实际后端、创建/采用时间、操作者、临时输出相对路径和最终输出相对路径。它是生成资产的唯一溯源记录。

## 服务端设计

新增独立的生成资产路由和服务，而不把业务塞入通用预览路由：

- 创建任务：验证 root、当前文件、项目标记、主题、尺寸和候选数；建立临时目录与 `request.json`；通过现有 `TaskExecutor` 按配置的 `agent.backend` 或请求指定且允许的后端发起任务。
- 查询任务/候选：只返回任务归属项目的安全元数据和通过预览资产接口访问的候选 URL。
- 读取结果：轮询任务运行状态并读取受限的 `result.json`；CLI 退出成功并不等同于候选已可用，只有校验通过的结果才进入 `awaiting_review`。
- 采用/删除/再生成：采用执行受控复制和原子 manifest 更新；删除只清理该任务内未采用候选；再生成或继续编辑创建新任务，并保留父任务/候选关系。

Agent 提示词只描述任务契约和具体需求，要求它使用自身可用的图像能力生成文件及 `result.json`。它不获得用户浏览器内容，不承担路径或权限决策，也不能决定最终保存位置。当前的 CLI 启动器丢弃 stdout，因此结果必须以文件协议交付。

配置新增一个生成资产小节，包含启用开关、默认/允许后端、每任务最大候选数、可接受图片类型和任务 TTL；实际 Agent 凭据仍只由现有后端配置或 CLI 自身管理。

## 前端设计

新增一个可延迟加载的图片资产面板模块，并通过 `ClawMatePanels` 的 surface-scoped registry 注册为 `imageAssets`。`preview.html` 为其提供明确的 grid column；`preview.js` 只负责在图片模式下提供入口、上下文及打开/关闭协调。面板遵从现有布局：推挤主内容、显式 `grid-column`、40px 头部、共享 `.panel-close-btn`、右侧面板互斥；移动端可使用现有的抽屉回退样式。

候选预览使用已有的文件预览 URL/图片渲染策略，绝不内联 Base64。候选卡片在任务仍在运行时显示不可操作状态；网络、权限或 Agent 失败显示可理解的错误和“重试”入口，不伪报已生成。

## 安全、审计与故障处理

- 所有项目路径均通过 `safe_path` 和项目 marker 校验；主题只能形成 `assets/generated/` 下的安全相对目录。
- 任务 ID 为服务端生成的 UUID；每个请求按 root、项目及认证会话授权，不能枚举其他项目任务。
- Agent 写入范围以临时目录为唯一可接受输出边界；服务端在读取、预览、采用和删除时重复校验。
- 用户文本按长度限制保存和传递；错误响应不回显 Agent 环境变量、CLI 输出中的密钥或内部绝对路径。
- 任务过期清理仅清理未采用且超过 TTL 的临时目录；已采用文件和 manifest 永不由清理任务删除。
- 部分失败保留任务元数据和可用候选供用户判断；manifest 更新使用临时文件加替换，避免半写入。

## 测试与验收

后端测试覆盖：项目/路径边界、请求校验、任务目录创建、Agent 后端选择、恶意 `result.json` 拒绝、合法候选预览、采用复制及 manifest 内容、重试关系、TTL 只删除未采用任务。

前端契约测试覆盖：图片模式入口、受控字段、1--4 候选限制、registry 注册、明确 grid column、右侧互斥、无 Base64、以及“文件变更只提醒不自动刷新”。

浏览器验收流程：打开图片预览，打开编辑态，提交一个模拟成功任务，检查候选卡片与采用后的 ClawMate 链接；再验证失败状态、桌面和移动布局、控制台无相关错误。真实 Agent 图像能力作为单独的配置依赖验收，不以测试替代。

## 实施顺序

1. 定义配置、任务模型、文件协议及纯服务层，并以失败测试驱动。
2. 增加受控 API、任务启动和结果校验，覆盖文件/授权边界。
3. 构建延迟加载的注册面板和预览入口，保持既有右侧面板契约。
4. 完成采用/manifest 与清理流程。
5. 跑 Python、前端契约和真实浏览器交互验收；在具备 Agent 图像能力的环境中进行一次手工端到端验证。
